# Pre-K–12 Teaching, Learning and School Operations Platforms

> A practical catalogue of online platforms used across early learning, primary and secondary education.
>
> **Scope:** Pre-K / Early Learning, K–12 teaching and learning, assessment, school administration and operations.
> **Australian context:** Platforms marked **🇦🇺** are Australian-developed, strongly Australian-focused, or commonly encountered in Australian schools.
> **Last reviewed:** 29 August 2026.
>
> **Provisioning note:** Where supported, student/class provisioning may be automated through integration services such as **Wonde** or **Clever**. Otherwise, schools may rely on native integrations, OneRoster, SCIM, APIs, CSV imports or manual administration.
>
> This is a **platform landscape**, not a recommendation that a school should adopt every product. Many products overlap substantially.

# 14. SIS Integration, Rostering & Provisioning

These tools sit **between the Student Information System (SIS) and downstream applications**. Their job is to reduce the amount of duplicated account, student, teacher, class and enrolment administration.

| Platform / Standard | Main use | Typical role | URL |
|---|---|---|---|
| **Wonde 🇦🇺/UK** | SIS integration, secure data sharing, automated rostering and app provisioning | SIS → Wonde → Learning / Operational Applications | https://www.wonde.com/au/ |
| **Clever** | Automated rostering, application provisioning, SSO and identity/access services | SIS → Clever → Learning Applications | https://www.clever.com/ |
| **1EdTech OneRoster** | Open interoperability standard for exchanging users, classes, courses and enrolments | SIS ↔ LMS / EdTech Applications | https://www.1edtech.org/standards/oneroster |
| **SCIM** | Standard for automated identity provisioning/deprovisioning | Identity Provider → Application | https://scim.cloud/ |
| **Native API Integration** | Direct vendor-to-vendor synchronisation using APIs | SIS / Identity Platform ↔ Application | Vendor-specific |
| **CSV / File Import** | Batch import of students, teachers, classes and enrolments | SIS export → File → Application import | Vendor-specific |
| **Manual Administration** | Individual account/class creation when no integration exists | Administrator → Application | Vendor-specific |

## Preferred Provisioning Pattern

```text
                     ┌────────────────────┐
                     │        SIS         │
                     │                    │
                     │ Students           │
                     │ Teachers           │
                     │ Classes            │
                     │ Enrolments         │
                     └─────────┬──────────┘
                               │
                 ┌─────────────┴─────────────┐
                 │                           │
                 ▼                           ▼
              Wonde                       Clever
                 │                           │
                 └─────────────┬─────────────┘
                               │
                    Automated provisioning
                         and rostering
                               │
           ┌───────────────────┼───────────────────┐
           │                   │                   │
           ▼                   ▼                   ▼
   Learning Platform     Digital Textbook       Other EdTech
           │                   │                   │
           ▼                   ▼                   ▼
   Students/classes      Student access       App-specific data
```

Where supported, the preferred model is:

```text
SIS → Wonde / Clever → Application
```

Other common models include:

```text
SIS → Native vendor integration → Application

SIS → OneRoster → Application

Identity Provider → SCIM → Application

SIS → CSV export → Manual application import
```

### Typical Data Being Provisioned

- Students
- Teachers
- Classes
- Subjects
- Courses
- Year groups
- Student-class enrolments
- Teacher-class relationships
- School/campus membership
- Email addresses
- Unique student/staff identifiers

### Common Provisioning / Rostering Tickets

- New student has no account
- New student is missing from a class
- Student appears in the wrong class
- Student remains enrolled in an old class
- Withdrawn student is still active
- Teacher cannot see a class
- Teacher change has not propagated
- Duplicate student accounts
- Incorrect email address or username
- SIS data has changed but downstream application has not updated
- Wonde/Clever sync has not completed
- Application has not consumed the latest roster
- CSV import contains invalid columns or values
- CSV encoding/delimiter problems
- Different systems are using different identifiers for the same student

### Triage Example

```text
"Three new Year 8 students cannot see the application."

        │
        ▼
How is the application provisioned?
        │
        ├── Wonde
        │     └── Check SIS → Wonde → Application sync/data sharing
        │
        ├── Clever
        │     └── Check SIS → Clever → Application sync/data sharing
        │
        ├── Native integration
        │     └── Check integration/synchronisation status
        │
        ├── OneRoster / SCIM / API
        │     └── Check provisioning logs and identifiers
        │
        └── CSV / Manual
              └── Check latest import and source data
```

> **Support principle:** Before troubleshooting the learning application itself, establish **where its students, staff, classes and enrolments come from**.

### Typical Payment Architecture

```text
Parent / Student
       │
       ▼
School Portal / Form / Application
       │
       ▼
Payment Gateway / Processor
(Fat Zebra / Stripe / Tyro / other)
       │
       ▼
Card / Bank / Wallet Network
       │
       ▼
Settlement / School Finance
```

### Common Payment Support Tickets

- Payment declined
- Payment appears successful but school system shows unpaid
- Duplicate charge
- Refund not appearing
- Receipt not generated
- Parent cannot reach payment page
- Payment link expired
- Gateway timeout
- Application received no payment callback/webhook
- Transaction exists in gateway but not school application
- Incorrect amount
- EFTPOS terminal unavailable
- Reconciliation mismatch
- Settlement discrepancy
- User paid under the wrong student/account

> **Triage principle:** Distinguish between the **school application**, the **payment gateway/processor**, and the **bank/card network**. “Payment isn't working” can mean three very different fires.

## Notes

- Product capabilities and branding change frequently.
- A product may belong to several categories.
- Schools often use integrations between an SIS/SMS, LMS, identity provider and specialist learning platforms.
- Authentication and rostering are important operational distinctions: two platforms that look similar educationally may create very different support workloads.
- For each application, document the authoritative source for users/classes and whether provisioning is via Wonde, Clever, OneRoster, SCIM, native API, CSV or manual administration.
- For payment-enabled applications, document the gateway/processor separately from the school application so transaction and reconciliation issues can be routed correctly.
- Always confirm local school configuration before assuming that the vendor's full feature set is enabled.
