# Spec: v0.4.0 priority accuracy

## Objective

Improve priority accuracy where the current deterministic engine can contradict an
analyst refinement or mistake historical, resolved, hypothetical, quoted, or test
language for an active incident. Add a dependency-free, offline evaluation harness so
future tuning can be measured against independently labelled tickets.

The release preserves the authoritative Impact x Urgency matrix. It improves the facts
fed into that matrix and makes insufficient evidence an explicit assessment state.

## Tech stack

Vanilla JavaScript ES modules, static HTML/CSS, and the dependency-free test harness in
`tests/tests.js`. No dependencies, backend, network calls, or persistent ticket storage.

## Commands

- Full test and privacy scan: `npm test`
- Evaluation corpus: `node tests/evaluate.mjs tests/fixtures/accuracy-corpus.json`
- Syntax check: `node --check <changed-js-file>`
- Source hygiene: `git -c core.whitespace=cr-at-eol diff --check`

## Project structure

- `js/engine/context.js`: clause status and modality classification
- `js/engine/analyzer.js`: evidence orchestration and manual refinements
- `js/engine/impact.js`, `urgency.js`: scoring from effective facets
- `tests/tests.js`: deterministic behaviour and contrast tests
- `tests/evaluate.mjs`: offline accuracy and safety metrics
- `tests/fixtures/accuracy-corpus.json`: documented example corpus schema
- `PRIORITY-FRAMEWORK.md`: canonical decision framework

## Code style

Use small pure functions returning explainable evidence records:

```javascript
return {
  status: 'resolved',
  active: false,
  evidence: [{ quote, meaning: 'The incident is stated as resolved' }]
};
```

Detectors establish facts; impact and urgency score those facts; only
`priority-matrix.js` emits P1-P4.

## Testing strategy

- Write a failing regression test before each behavioural fix.
- Pair every positive context rule with an active counterexample.
- Assert manual facets through final impact, urgency, and priority, not display state.
- Keep the complete 429-test baseline and privacy scan green.
- Evaluate independently labelled fixtures without importing or transmitting them.

## Boundaries

- Always: preserve explainability, manual impact/urgency authority, local-only analysis,
  and the existing matrix.
- Ask first: change the matrix, add dependencies, add network calls, or store ticket text.
- Never: treat `urgent`, `P1`, historical quoted failures, hypotheses, or test scenarios
  as proof that harm is active now.

## Success criteria

- Manual `spreading`, `driver`, and `harm` refinements affect scoring when decision-
  relevant and are covered by regression tests.
- A resolved current update is not re-escalated by an older quoted failure.
- Conditional, exercise, design, and UAT/test statements do not become active incidents.
- Active incidents using similar wording retain their existing priorities.
- Unassessed input exposes an explicit assessment state and no actionable suggested
  priority, while retaining the internal matrix result for compatibility.
- The offline evaluator reports exact priority accuracy, impact/urgency accuracy, P1
  precision/recall, dangerous under-prioritisation, coverage, and a confusion matrix.
- Documentation identifies the release as v0.4.0 and the complete suite passes.

## Open questions

- Threshold and weight calibration remains pending until independently labelled,
  anonymised production tickets are supplied. The evaluator makes that work repeatable.
